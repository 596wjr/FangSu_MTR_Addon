# 1.6.0 票务界面与设备

## 原售票机界面

票务交易页直接继承 `ui/ticketMachine/TicketMachineMainScreen`，保留原有 256×196 外框、左侧六档张数、中部彩色线路与车站列表、右侧票额与数字键盘、底部确认/取消以及原确认页。售卡和补票业务也使用同一界面。

选择目的站、票额、产品、数量或支付方式后，约 120 毫秒内自动请求服务端报价；数字键盘输入时也自动更新。界面没有“查看报价”步骤，确认页显示金额及实际扣款数量，文字不绘制阴影；未收到当前选择的有效报价时不能付款。服务端确认付款成功后关闭交易页，失败时保留界面提示原因；玩家提前关闭页面，成功回包也不会重新打开它。每条报价和错误回包按会话、设备、请求序号匹配，旧回包不能覆盖新选择；报价定时自动续期。

售票机的右侧票额栏继续支持按票额购买单程票，实际扣款为服务端按票额与张数计算的金额。按站选票则由服务端按网络规则计算票额。只能出售单程票、联程票；售卡机默认只出售 IC 卡，日票需管理员分别开启。一日、三日、七日通从首次成功进站起分别连续有效 24、72、168 小时，修改产品不追溯修改旧票快照。

普通右键打开交易，管理员持扳手右键机器直接打开管理。闸机从扳手设置内进入票务管理，保留门翼等原配置。IC、日票、联程票不列入创造标签页。

## 固定模型与屏幕

新放置售票机默认选择经典的“北京地铁售票机”。模型列表复用原闸机的 `ModelSelectScreen`；详情显示“北京地铁售票机”或“北京地铁售卡机”。模型选定后使用资源包定义的固定坐标、碰撞、UV 与屏幕参数，管理页不提供外观高级设置或逐项修改。

经典机身的操作斜面由 Blockbench 元素绕 `origin` 旋转得到。加载器现在执行元素旋转，修复斜面与屏幕错位；新旧模型均同步机身、屏幕、碰撞的贴墙偏移，物品显示完整机身。经典款仅渲染顶部 LED，不在原操作面前额外叠加业务屏，方块与物品使用同一规则。

屏幕用 `|` 分隔轮播语言，分隔符不显示；`\n` 表示同页换行。默认售票机为 `服务中|In Service`，售卡机为 `正常服务\nIn Service`。短文字居中，长文字保持字号滚动，使用点阵效果。文案、语言切换间隔可编辑并恢复默认，补票屏仅显示一个补票业务选项。

单程票保留底图印刷的右上角中英文标题，不再清底重画名称；票额、编号仍动态更新。

## 资源包票务预设

任意资源包可放置 `assets/<命名空间>/ticketing/presets/<文件名>.json`。游戏自动发现所有命名空间，无须覆盖方速的 `custom_blocks.json`。内置 `municipal.json` 提供 IC、一日、三日、七日通产品模板。

管理员在产品页点“新增票务产品”可选空白或资源包产品预设。套用模板时生成新的产品 ID，并补入其资源文件声明的网络与联合组。网络、产品、联合组页也支持一次导入整套预设。同 ID 已有配置保留原值；导入只修改草稿，保存后由服务端统一检查权限、目录版本和引用关系。资源包不会自动改动既有世界目录，也不会自动开启任何设备的销售白名单。

文件格式如下（下面仅为通用格式示意，中国铁路扩展另行提供内容）：

```json
{
  "name": "资源包票务目录",
  "networks": {
    "example:network": {
      "name": "示例网络",
      "minimumBalance": 0,
      "rule": { "mode": "FIXED", "fixed": 2 }
    }
  },
  "unions": {
    "example:union": {
      "name": "示例联合组",
      "texture": "example:ticketing/union.png",
      "networks": ["example:network"]
    }
  },
  "products": {
    "example:ic": {
      "name": "示例交通卡",
      "kind": "IC",
      "price": 0,
      "initialBalance": 0,
      "style": "example:ticketing/ic.json",
      "networks": [],
      "unions": ["example:union"]
    }
  }
}
```

映射键即稳定 ID；票种为 `SINGLE`、`IC`、`ITINERARY`、`DAY`。日票用 `validDays` 指定天数，联程票用 `legs`、`ordered`、`validHours` 指定权益与时限。导入后仍需按设备选择出售产品、绑定网络闸机建立车站成员。

## 双版本游戏验收

本次不运行 Gradle，也未进游戏实测。分别在 MTR3、MTR4 检查：

1. 对照原售票机确认界面布局、张数、彩色线路、车站、票额及数字键盘；购卡、充值、补票使用同一界面，管理只能由管理员扳手进入。
2. 快速切换车站、张数、产品和支付方式，检查总额、物品实扣数量自动更新。输入票额/充值数字时实时更新，慢回包不得恢复旧价格；未完成报价不能付款，连点只能完成一笔。
3. 检查新放机器默认经典模型、四向贴墙、斜面、屏幕、碰撞、完整物品模型；模型详情不含技术字段，没有高级外观编辑。
4. 检查两种默认屏幕文字、语言轮播、同页换行、长文本滚动、恢复默认、重载资源和移除机器后的资源释放。
5. 新售卡机默认仅 IC 卡；分别仅开启一日、三日、七日通，再测任意组合。检查三张票面的颜色、地标、编号和有效期以及 24/72/168 小时边界。
6. 在自有资源包添加预设文件，新增产品选模板，整套导入网络/联合组/产品；检查同 ID 不覆盖，缺失引用保存时提示，未保存不生效。测试资源重载后发现新增预设。
7. 用 MTR 余额和物品货币各测购票、充值、补票；检查整数计费、物品向上取整、背包满、旧报价、多人配置、重登与服务端重启。

## 名称与语言

已签发票卡的物品名称读取产品快照，例如“市政交通一日通”“市政交通三日通”“市政交通七日通”，已有票卡也直接适用；保留玩家通过铁砧设置的自定义名称。提示中不再重复添加产品名。

票卡的网络、余额、有效时长、进站状态、有效期、编号，闸机检票结果，以及交易界面的状态、确认、支付方式使用语言文件。闸机和服务端校验错误发送翻译键，由各玩家客户端翻译，不在服务端拼接中文。日期统一显示为 yyyy-MM-dd HH:mm。产品、网络、联合组本身的名称属于世界或资源包内容，保留作者定义。

设备上的购票 / Buy Ticket、购卡 / Buy Card、充值 / Top Up、补票 / Fare Adjustment 大按钮始终同时显示中英文。既有票面底图和机身细节贴图不强制改成双语。

语言验收：在中文和 English (US) 下分别查看一日、三日、七日通的手持名称、背包标题与提示；检查英文的验票成功、票额不足、未进站、错误网络、充值、付款确认等提示。多人服务器同时使用两种语言的客户端时，检票结果应分别显示各自语言。检查机器的大按钮为中英两行且不重叠。

## 与原版 MTR 对齐的金额与站名

金额显示采用原版 MTR 的前缀 `$`，例如 `Balance: $20`、`Fare: $2`，不使用 `yuan`。金额数值和整数计费规则不变。

IC 卡进出闸直接复用原版 `gui.mtr.enter_barrier`、`gui.mtr.exit_barrier` 翻译，余额使用本卡余额。其他票种与换乘提示也包含实际站名；日票出站不显示为另收一次普通行程票价。站名按原版替换 `|` 为空格，MTR3 显示 `站名 (分区)`，MTR4 显示 `站名 (分区1/分区2/分区3)`，保留世界里定义的真实名称。入站信息提示也遵循此格式。
